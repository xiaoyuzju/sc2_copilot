# 灰机 Wiki 全地图表格与时间语义分析

日期：2026-07-21

## 结论

现有快照完整包含 15 张基础地图，共 149 张表、1,609 个原始 DOM 行；逐页统计与 [`manifest.json`](../../data/sources/huiji/2026-07-21/manifest.json) 一致。与地图时间或触发直接相关、或为其提供分支条件的候选表共 82 张、889 个原始行，其余主要是单位属性、技能冷却、概率/组成附表和全站地图导航。

全量表格证明不能把地图时间表建模成单一的 `(地图, 秒数, 文案)`：至少需要游戏绝对时间、阶段相对时间、剩余倒计时、条件触发、重复间隔五类时钟语义，并支持不确定范围、公式、备选分支、同秒多事件和合并单元格继承。

灰机 Wiki 是本项目选定的数据基线，但它是社区维护资料，不是官方来源。本报告只描述 2026-07-21 快照里的表格，不声称数据代表官方或当前游戏版本事实。Keiframe 仍只用于差异检查；边界见 [`keiframe-map-schedule-inventory.md`](keiframe-map-schedule-inventory.md)。

## 快照边界

- 抓取方式：浏览器 DOM；时间见 manifest 的 `capture_started_at` 与 `capture_finished_at`。
- 15 个 JSON 的 `table_count`、行数、URL 和连续 `table_index` 均与 manifest 一致。
- 所有页面的 `page_last_modified` 都为空，不能从快照得到稳定的页面修改时间。
- `table_index` 在本文中从 0 开始；行数包含表头、展开标题和因合并单元格产生的布局行。
- 快照保存表格单元格及 `row_span`/`column_span`，但不保存表格外的章节标题和邻接正文。若表内未写明时间锚点，本文标为“锚点未确认”，不从页面顺序推断。
- 页面末尾通常有一张 15 地图导航表；单位技能表中的准备时间、持续时间和冷却时间不属于地图时间线，未计为时间表事件。

## 五类时钟语义

| 类型 | 定义 | 快照实例 |
|---|---|---|
| 游戏绝对时间 | 从本局开始计时的 `MM:SS` 时间点 | 湮灭快车进攻波次、机会渺茫双种族时间、聚铁成兵波次 |
| 阶段相对时间 | 相对于夜晚、主目标波次、采集阶段等阶段锚点的经过时间 | 亡者之夜“夜晚次数 + 触发时间”、死亡摇篮“主目标波次启动后” |
| 剩余倒计时 | 阶段倒计时降到某值时触发 | 净网行动“剩余时间”、营救矿工“触发倒计时” |
| 条件触发 | 到达区域、前一目标完成、建筑数量比较等状态条件 | 克哈裂痕碎片、净网行动奥罗娜抵达区域、机会渺茫路径选择 |
| 重复间隔 | 从某锚点开始按间隔、次数或公式反复发生 | 熔火危机岩浆间隔、亡者之夜感染体冷却、营救矿工通用骚扰重复 |

时间“基准”和时间“数值形状”必须分开。数值形状至少有精确值、`±` 窗口、范围、`n` 递推公式和无法安全解析的来源表达式。表中同时出现时间与条件时，只有明确写出“或”“后”等关系的行才能编译为逻辑表达式；否则保留为锚点/关系未确认。

## 跨地图共同形状

1. 同一事件可能分散在主表、护卫表、概率附表和路线附表，也可能在汇总表中重复出现。
2. 一个逻辑波次可能占多个 DOM 行；`rowspan` 表示父字段继承，`colspan` 常表示整组说明、等待时间或双分支共享值。
3. 时间规则可以是精确时刻、误差窗口、阶段偏移、倒计时、完成事件后的延迟、条件逻辑或无限递推。
4. 分支至少包括敌方种族、地图布局/路线、概率备选和状态比较；“分支选择条件”与“分支内事件”应分开保存。
5. 同秒多事件和一行多目标都存在，事件 ID 不能只由地图与秒数组成。
6. 并非所有抓到的秒数都是时间线：单位技能冷却属于百科属性，不能由通用时间正则自动纳入。

## 推荐的最小完整模型

采用三层模型，避免原始页面结构直接泄漏到运行时：

1. **Raw snapshot**：现有 JSON 原样保留 URL、抓取时间、表/行/单元格、`row_span` 和 `column_span`，作为审计依据。
2. **Table adapters**：每张相关表有显式适配器，先展开合并单元格、识别表内字段、保留分支组和重叠关系；锚点或逻辑不明确时产生诊断，不猜测。
3. **Compiled events**：只把已确认语义编译成随程序发布的规范化事件；程序运行时不读取 Wiki 或 raw 表。

规范化核心结构建议为：

```text
CompiledEvent {
  map_id
  variant_id?
  event_id
  trigger: Trigger
  facts: Fact[]
  source_ref: SourceRef[]
  runtime_support: supported | manual_context | unsupported
}
```

`Trigger` 是强类型表达式：`AtGameTime`、`AtStageElapsed`、`AtStageRemaining`、`WhenCondition`、`After`、`AnyOf`、`AllOf`、`Repeat`。时间值支持精确毫秒、误差窗口、递推式和暂不可解析的来源表达式；后者不能进入自动提醒。

`Fact` 只保存跨地图稳定的事实：事件类别/波次、位置、路线、目标、规模/科技、生命/护盾、数量/组成、概率或备选组。提示文案由本项目生成；原始单元格文本不作为运行时事件接口。

`SourceRef` 至少包含 `source_url`、快照相对路径、`table_index`、逻辑行/单元格引用和抓取批次。一个事件允许多个来源引用，用来表达主表与附表合并、汇总表重复以及 Keiframe 差异记录。

`runtime_support` 使“数据已抓到”和“初版能自动触发”分离：纯游戏绝对时间通常可支持；需要人工选择的分支为 `manual_context`；净网 OCR、未确认锚点和其他视觉条件为 `unsupported`。这样能完整保留未来能力，又不会违反当前不做视觉识别的范围。

采用后的完整设计见 [Map Schedule Design](../map-schedule-design.md)。
