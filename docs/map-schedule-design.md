# Map Schedule Design

本设计基于 2026-07-21 抓取的 15 张地图、149 张表和 1,609 个原始 DOM 行。证据与逐地图分析见 [Huiji All-map Table Analysis](./research/huiji-all-map-table-analysis.md)，Keiframe clean-room 比较边界见 [Keiframe Map Schedule Inventory](./research/keiframe-map-schedule-inventory.md)。

## Goals

- 无损保留灰机 Wiki 表格，任何运行事件都能追溯到来源单元格。
- 保持开局时间、阶段时间、剩余倒计时、条件和重复间隔的原生含义。
- 让首版不依赖视觉识别，同时不把暂时无法触发的数据丢弃或伪装成绝对时间。
- Keiframe 只产生差异报告，不决定发布值、运行模型或提示文案。

## Three-layer pipeline

```text
raw DOM snapshot -> reviewed table adapters -> compiled schedule events
```

### Raw DOM snapshot

保存页面 URL、采集时间、表格、行、单元格类型、原文以及 `row_span`/`column_span`。它是审计输入，不由运行中的应用读取。

### Reviewed table adapters

每张相关表通过显式表头签名匹配。适配器负责展开合并单元格、连接主表与附表、保留分支并去除页面中的重复汇总；不能确认时间锚点或逻辑关系时产生诊断，不猜测。

不用一个通用正则扫描所有秒数，也不为 15 张地图分别建立互不兼容的运行时结构。

### Compiled schedule events

审核通过的规范化 JSON 在 Rust 构建时解析、校验并嵌入可执行文件。原始网页快照和 Keiframe 差异报告不进入运行时数据。

## Compiled model

```text
CompiledEvent {
  map_id
  variant_id?
  event_id
  trigger: Trigger
  facts: Fact[]
  source_refs: SourceRef[]
  runtime_support: automatic | manual_context | unsupported
}
```

`event_id` 是稳定标识，不能只由地图和秒数组成，因为同秒多事件和一行多目标都存在。

### Trigger

`Trigger` 是封闭的强类型表达式：

- `AtGameTime`：从本局开始计算的精确时间或明确窗口；
- `AtStageElapsed`：从夜晚、主目标或其他阶段开始计算；
- `AtStageRemaining`：阶段倒计时降到指定值；
- `WhenCondition`：区域、目标完成或其他明确条件；
- `After`：前一事件发生后的延迟；
- `AnyOf` / `AllOf`：只在来源明确写出逻辑关系时组合触发器；
- `Repeat`：按间隔、次数或有界递推发生。

无法安全解析的来源表达式可以保留在适配器诊断中，但不能进入自动调度路径。

### Fact

`Fact` 保存跨地图稳定的结构化事实：事件类别、波次、位置、路线、目标、规模等级、科技等级、生命或护盾、数量或组成、概率和备选组。应用提示语从这些事实生成，不复制灰机 Wiki 说明文字，也不使用 Keiframe 的简写字符串。

### SourceRef

`SourceRef` 至少包含来源 URL、快照批次、快照相对路径、`table_index` 和逻辑行或单元格引用。一个事件可以引用多个来源，用于连接主表、护卫表、概率附表或重复汇总表。

## Runtime support

### Automatic

只依赖本局经过时间以及已经明确选择的地图/分支。调度器直接使用 6119 状态提供的游戏时间。

### Manual context

需要一个明确但 6119 状态不提供的阶段锚点或分支。玩家点击“阶段开始”或“目标启动”时，应用记录当时的游戏时间并启动相应阶段时钟；不得把预计阶段时间作为默认锚点。

适用候选包括亡者之夜的夜晚阶段、营救矿工的撤离阶段和死亡摇篮的主目标阶段。具体按钮只有在对应适配器能证明锚点和事件关系时才出现。

手动锚点是当前对局的临时状态：

- 创建时记录当前会话 ID、阶段 ID 和游戏经过时间；
- 重新标记会原子地替换同一阶段锚点，并重新计算尚未发生的阶段事件；
- 清除后停止该阶段的提醒，不回放已经错过的事件；
- 离开对局、开始新局或检测到游戏时间重置时清除全部锚点；
- 不写入用户设置，不跨对局恢复。

锚点控件只在覆盖层的临时交互模式中出现。覆盖层平时鼠标穿透；可配置全局热键打开当前地图面板，再次按热键或按 Esc 关闭面板并恢复穿透。面板只显示当前地图已有、且适配器声明为 `manual_context` 的锚点操作。离开对局时面板自动关闭。

全局热键只切换本应用窗口状态，不生成、转发或模拟游戏输入。具体默认键位在实现前另行决定；热键注册失败时必须在设置和诊断中显示，并保留托盘或设置窗口入口作为操作后备。

### Unsupported

依赖持续 OCR、视觉状态、页面中未确认的锚点，或者仍为无法安全解析的表达式。数据继续保留并参与来源审查，但首版不安排提醒。

“净网行动”的已净化节点数和阶段剩余倒计时属于此类；未来视觉识别只需提供状态和时钟锚点，不改变事件结构。

## Scheduling rules

- 不将阶段相对事件转换成估计开局时间。
- 不以 `(map_id, second)` 唯一标识事件。
- 暂停、倒退、重新开局和手动重设锚点必须作为显式状态迁移处理。
- 清除或替换锚点不能重复触发已经在当前会话中发出过的同一事件。
- 同一时刻的多个事件分别保存，展示层可以合并显示但不能修改事实身份。
- `unsupported` 事件不得进入“下一事件”计算或触发提醒。
- Keiframe 差异只能生成诊断，不能自动修改编译事件。

## Alert delivery

- 使用一个持久化的全局提醒提前量，默认 30 秒；首版不提供逐地图或逐事件提前量。
- 当受支持事件首次进入 `[event_time - lead_time, event_time)` 窗口时，发送一次播放请求和弹窗提醒。
- 去重身份为当前 `session_id + event_id`；替换手动锚点或重新计算事件时间不会清除已经发送的身份。
- 覆盖层可以持续显示下一事件及其倒计时，不受一次性通知去重影响。
- 事件到点时不再次请求播放或弹出通知。
- `unsupported` 事件不显示倒计时，也不参与通知窗口判断。
- 调度器解析完绝对时间、手动阶段锚点和分支后，以最终事件时刻建立提醒批次；只有最终时刻完全相同的事件才合并。
- 一个批次只调用一次提醒播放端口并显示一个弹窗，弹窗按稳定顺序列出全部事件；覆盖层仍保留各事件的独立条目。
- 弹窗由 egui 覆盖层中的临时提示卡片实现，不调用 Windows 通知中心，不请求前台焦点，也不进入系统通知历史。
- 批次发送成功后，把其中每个 `event_id` 分别记入当前会话的已通知集合；批次不是新的领域事件 ID。
- 不因提醒提前窗口重叠而合并不同最终时刻的事件。
- 首次连接、中途启动、同局重连或游戏时间向前跳跃后，`event_time <= current_game_time` 的未通知事件直接转为 `missed`，不请求播放、不弹出通知。
- 恢复时仍满足 `current_game_time < event_time`、但已经进入提前窗口的事件立即通知一次。
- `missed` 只属于当前会话，不会因为后续时间采样或手动锚点变化而补发；覆盖层默认不把它作为下一事件。
- 同一会话重连沿用 `notified` 和 `missed` 集合；只有确认进入新会话时才清空。
- 提醒播放端口是交付层的非阻塞、尽力而为输出；调度器不引用具体音频资源、TTS 或播放库。
- 播放接口失败只进入诊断，不回滚弹窗、不清除已通知状态，也不自动重试同一批次。

## Validation gates

- 每个编译事件至少有一个可解析的 `SourceRef`；
- 所有事件 ID 在地图和变体内唯一；
- 所有时间值和窗口非负，精度不因格式化而丢失；
- `automatic` 事件不能引用阶段倒计时、OCR 或视觉条件；
- `manual_context` 事件必须声明用户可以明确执行的锚点动作；
- 手动锚点的创建、替换、清除和会话结束清理都有状态迁移测试；
- 覆盖层穿透/交互切换、Esc 退出、会话结束关闭面板和热键注册失败后备入口都有测试；
- 默认和自定义提前量、单次通知、到点不重复以及重新锚定后的去重都有确定性测试；
- 同刻批次的稳定排序、单次播放请求、逐事件去重以及相邻但不同时刻不合并都有测试；
- 使用成功、失败和无操作三种播放端口替身验证调度结果不受具体声音实现影响；
- 覆盖层提示卡片不激活窗口、不改变游戏前台状态，也不创建 Windows 系统通知；
- 中途启动、断线恢复、跨越提醒窗口和跨越事件时刻分别验证立即提醒或标记错过，不产生补发风暴；
- 主表和附表合并、同秒事件、分支与合并单元格均有固定快照测试；
- 构建在未知表头、未处理字段或不明确触发关系上失败，而不是静默忽略。
